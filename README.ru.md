# Badaction

Badaction — лёгкая самостоятельная доска с открытым исходным кодом для командных
ретроспектив. Учётные записи пользователей не нужны: доступ привязан к
анонимной сессии браузера и членству в конкретной доске.

Интерфейс приложения сейчас доступен на русском языке, а документация проекта —
на английском, русском и испанском.

![Доска ретроспективы Badaction с колонками, сгруппированными карточками, голосами и задачей](docs/assets/product-board.png)

## Возможности

- Создание доски без регистрации учётной записи.
- Возврат с главной страницы к активным собственным и общим доскам в том же
  браузере.
- Приглашение участников по ссылкам с ограниченным сроком действия и числом
  использований.
- Раздельные права владельца и участника.
- Создание, переименование, изменение порядка и удаление до десяти колонок с
  отдельным лимитом голосов для каждой.
- Добавление карточек с необязательным автором, редактирование собственных
  карточек и их перемещение указателем, касанием или с клавиатуры.
- Голосование, независимая сортировка каждой колонки по числу голосов без
  изменения сохранённого порядка карточек, группировка связанных карточек и
  преобразование результатов в назначаемые задачи. При перемещении карточки из
  этого режима видимый порядок затронутых колонок становится сохранённым.
- Приостановка добавления карточек или голосования, перевод доски в режим только
  для чтения и сброс голосов владельцем.
- Обновления почти в реальном времени через PostgreSQL `LISTEN/NOTIFY` и SSE с
  периодической сверкой состояния как резервным механизмом.
- Экспорт доски в JSON, CSV или Markdown.
- Автоматическое истечение срока действия досок через настраиваемый период
  хранения.

## Быстрый запуск

Понадобится Docker с BuildKit и команда Compose v2 (`docker compose`).

```bash
git clone https://github.com/Rutboy/badaction.git
cd badaction
docker compose --profile app up --build
```

Откройте <http://localhost:3000>. Одноразовый контейнер миграций применит
миграции базы данных до запуска приложения.

Стандартные реквизиты Compose — предсказуемые значения для разработки, а оба
опубликованных порта привязаны к интерфейсу обратной петли. Не открывайте эту
конфигурацию для сети. Остановите стек сочетанием `Ctrl+C`, затем выполните:

```bash
docker compose --profile app down
```

Том `postgres-data` сохраняется. Для окончательного удаления локальных досок и
базы данных запускайте `docker compose --profile app down --volumes` только
тогда, когда эти данные можно безвозвратно удалить.

Разработка вне контейнеров описана в разделе
[Начало работы](docs/ru/getting-started.md).

## Требования

- Docker с BuildKit и Compose v2 для быстрого контейнерного запуска. Проект не
  устанавливает минимальную версию Docker или Compose.
- Node.js 22.23.2 и npm 10.9.8 для разработки из исходного кода; обе версии
  закреплены в `.nvmrc` и `package.json`.
- PostgreSQL 16. Миграции зависят от поведения PostgreSQL 16; другие основные
  версии не поддерживаются.
- Playwright 1.62.1 и соответствующая сборка Chromium — только для браузерных
  тестов и создания скриншотов. Формальной матрицы поддержки разных браузеров
  нет.

## Самостоятельный хостинг

Репозиторий содержит образы мигратора и приложения, работающие без прав `root`,
а также переопределение Compose для production, которое требует реквизиты оператора.
Это базовая конфигурация для одного хоста: HTTPS, обратный прокси, резервное
копирование, мониторинг и достаточный запас подключений PostgreSQL необходимо
организовать отдельно.

До открытия экземпляра прочитайте [Руководство по развёртыванию](docs/ru/deployment.md).
В частности, для SSE нужно отключить буферизацию на прокси, а подключение к базе
данных должно сохранять состояние сессии: пул только для транзакций несовместим
со слушателем PostgreSQL и блокировкой очистки.

## Конфигурация

В production обязательны:

- отдельные административная роль PostgreSQL, роль мигратора и ограниченная роль
  приложения с разными паролями длиной не менее 32 символов;
- `DOCKER_MIGRATOR_DATABASE_URL` и `DOCKER_RUNTIME_DATABASE_URL` для PostgreSQL
  16 со схемой `public`;
- точный HTTPS-источник в `DOCKER_APP_ORIGIN` без завершающего `/`;
- попарно различные `DOCKER_VISITOR_TOKEN_SECRET`,
  `DOCKER_BOARD_ACCESS_SECRET` и `DOCKER_RATE_LIMIT_KEY_SECRET` длиной не менее
  32 символов.

По умолчанию новые доски хранятся 90 дней, а общий лимит карточек равен 500 на
доску. Доверие к прокси, расписание очистки, порты, переопределение Docker и тестовые
настройки описаны в [Конфигурации](docs/ru/configuration.md).

## Технологии

- Next.js App Router и React отрисовывают загруженную на сервере доску и
  интерактивный интерфейс.
- TypeScript и Zod задают типы приложения и проверяют входные данные запросов.
- Prisma предоставляет клиент базы данных для сервисного слоя и прямые
  миграции.
- PostgreSQL хранит всё состояние продукта, корзины ограничения частоты,
  уведомления об обновлениях и координацию очистки.
- dnd-kit обеспечивает перетаскивание указателем, касанием и с клавиатуры.
- Tailwind CSS, примитивы Radix, компоненты на основе shadcn/ui, Lucide и Sonner
  формируют интерфейс.
- Встроенное средство запуска тестов Node.js и Playwright покрывают модульные,
  интеграционные и браузерные сценарии.
- Docker собирает отдельные образы мигратора и автономной среды выполнения.

Сведения об атрибуции приведены в [уведомлениях о сторонних компонентах](THIRD_PARTY_NOTICES.md),
а уведомления о пакетах среды выполнения — в создаваемом манифесте лицензий
автономной сборки.

## Безопасность, приватность и хранение

Badaction работает без учётных записей, но не обеспечивает абсолютную
анонимность. Приложение хранит подписанную cookie посетителя с атрибутом `HttpOnly`
и выводит из неё идентификаторы в рамках доски; оператор сервера, провайдер
хостинга или обратный прокси при этом могут сохранять сетевые журналы.

UUID доски — только адрес, а не реквизит доступа. Для чтения или изменения
доски также нужны активная анонимная сессия и членство. URL приглашений являются
предъявляемыми реквизитами доступа: передавайте их конфиденциально и не
помещайте в журналы, скриншоты, аналитику или публичные чаты. При потере или
очистке cookie посетителя
теряются связанные членства и идентификатор голосования; участнику потребуется
новое приглашение, а восстановление владельца требует помощи оператора.

Срок действия досок и дочерних данных завершается через
`BOARD_RETENTION_DAYS` (по умолчанию 90 дней). Очистка выполняется
автоматически, но операторы обязаны проверять его работу и самостоятельно
управлять резервными копиями базы и инфраструктурными журналами. Подробнее см.
[Безопасность и приватность](docs/ru/security-and-privacy.md). Об уязвимостях
сообщайте через [SECURITY.md](SECURITY.md), а не в публичном обращении.
