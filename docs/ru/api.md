# API веб-приложения

Badaction предоставляет конечные точки HTTP, которыми пользуется его собственный
веб-интерфейс. Это внутренний API приложения, документированный для того, чтобы
участники разработки и операторы самостоятельного хостинга понимали работающую
систему. Это **не стабильный публичный контракт интеграции**: пути конечных точек,
поля запросов и ответов, коды ошибок и лимиты могут меняться вместе с
интерфейсом без гарантий
семантического версионирования или окна совместимости.

Для переноса данных доски из приложения используйте экспорт. Если вы создаёте
внешний клиент, закрепите его на конкретном коммите Badaction и тестируйте при
каждом обновлении.

Источником истины служит реализация в `src/app/api/`, её валидаторы и сервисы.
Эта страница намеренно резюмирует интерфейс, а не определяет отдельную схему.

## Общие правила

- Базовый путь — `/api` на том же источнике, что и веб-приложение.
- Конечные точки JSON используют JSON в UTF-8. JSON-мутации требуют
  `Content-Type: application/json` и обычно принимают не более 16 KiB.
- Приложение устанавливает и читает подписанную cookie `visitor_token`.
  Запросы браузера используют реквизиты того же источника; режима аутентификации
  через предъявляемый токен или ключ API нет.
- Защищённые операции доски требуют активной анонимной сессии и активного
  членства в этой доске. UUID доски — только адрес.
- Запросы, меняющие состояние, проверяются по метаданным браузера о том же
  источнике. При наличии заголовка `Origin` он должен точно совпадать с каноническим источником
  приложения.
- Ответы доски, мутаций, доступа, экспорта и ошибок используют
  `Cache-Control: no-store`.
- Создаваемые приложением ID — UUID v4. Маршруты содержимого требуют синтаксис
  UUID v4; маршруты управления доступом принимают более общий синтаксис UUID.
  Все принятые UUID приводятся к нижнему регистру.
- Временные метки — строки ISO 8601. Ревизии доски — канонические неотрицательные
  десятичные строки, поскольку происходят из PostgreSQL `bigint`.
- Если не указано иное, успешные JSON-мутации возвращают `200`. Конечные точки
  создания возвращают `201`; некоторые удаления доступа и доски — `204` без
  тела ответа.

## Модель доступа

Cookie необходима, но сама по себе не предоставляет доступ ко всем доскам.
Сервер разрешает её в анонимную сессию, а затем ищет членство в доске:

- `OWNER` может управлять настройками, доступом, колонками, группами, задачами,
  сбросом голосов и удалением доски.
- `PARTICIPANT` может читать и экспортировать доску, голосовать, создавать
  карточки, управлять карточками, созданными текущим членством, переименовывать
  это членство и выходить из доски.

Если у сессии нет активного членства, доступ в рамках доски обычно маскируется как
`404 BOARD_NOT_FOUND`. Клиенты не должны считать знание UUID авторизацией.
Полная модель описана в [Архитектуре](architecture.md) и
[Безопасности и приватности](security-and-privacy.md).

## Снимок доски

`GET /api/boards/{boardId}?limit=50` возвращает авторитетный снимок,
используемый интерфейсом. `limit` применяется к первой странице
верхнеуровневых элементов каждой колонки; по умолчанию он равен 50 и должен
находиться между 1 и 100.

Высокоуровневая форма ответа:

```json
{
  "id": "board UUID",
  "title": "Retrospective title",
  "revision": "12",
  "createdAt": "ISO timestamp",
  "expiresAt": "ISO timestamp",
  "settings": {
    "cardsEnabled": true,
    "votingEnabled": true,
    "readOnly": false
  },
  "viewer": {
    "role": "OWNER",
    "displayName": "Владелец"
  },
  "capabilities": {
    "canManageSettings": true,
    "canManageAccess": true,
    "canManageColumns": true,
    "canManageGroups": true,
    "canManageActionItems": true,
    "canResetVotes": true,
    "canDeleteBoard": true,
    "canLeaveBoard": false,
    "canCreateCards": true,
    "canVote": true
  },
  "columns": [],
  "remainingVotesByColumn": {},
  "actionItems": []
}
```

Каждая колонка содержит `id`, `title`, `position`, `voteLimit`, страницу
`items`, `totalCount` и `nextCursor`. Элементом может быть карточка или группа.
Карточки включают текст, необязательного автора, порядок, состояние голосования,
возможности просматривающего пользователя и временные метки. Группы включают
карточки, ID основной карточки, необязательное название, агрегированное
состояние голосования, возможности и временные метки. Задачи включают текст,
необязательного исполнителя, состояние выполнения, порядок, необязательный ID
исходной карточки и временные метки.

## Семейства конечных точек

### Доски

| Метод и путь                   | Доступ                                                | Запрос                                                                     | Результат                                                                                                                         |
| ------------------------------ | ----------------------------------------------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/boards`             | Cookie посетителя; существующее членство не требуется | `{title}`                                                                  | `201` с ID и URL доски, названием, ревизией и временными метками. Также создаёт сессию, членство владельца и стандартные колонки. |
| `GET /api/boards/{boardId}`    | Участник доски                                        | Параметры `{limit?}`                                                       | Описанный выше снимок доски.                                                                                                      |
| `PATCH /api/boards/{boardId}`  | Владелец                                              | Одно или несколько из `{title?, cardsEnabled?, votingEnabled?, readOnly?}` | Текущая ревизия, название и настройки.                                                                                            |
| `DELETE /api/boards/{boardId}` | Владелец                                              | Без тела запроса                                                           | `204`; удаляет доску и зависимые данные.                                                                                          |

Конечной точки со списком всех досок текущего браузера нет.

### Колонки

| Метод и путь                                         | Доступ   | Запрос                                            | Результат                                                                   |
| ---------------------------------------------------- | -------- | ------------------------------------------------- | --------------------------------------------------------------------------- |
| `POST /api/boards/{boardId}/columns`                 | Владелец | `{title, voteLimit, placement, expectedRevision}` | `201` с ревизией и колонкой.                                                |
| `PATCH /api/boards/{boardId}/columns/{columnId}`     | Владелец | `{title?, voteLimit?, expectedRevision?}`         | Ревизия и колонка. При изменении `voteLimit` обязателен `expectedRevision`. |
| `POST /api/boards/{boardId}/columns/{columnId}/move` | Владелец | `{placement, expectedRevision}`                   | Ревизия и колонка.                                                          |
| `DELETE /api/boards/{boardId}/columns/{columnId}`    | Владелец | Явная форма удаления с `expectedRevision`         | Ревизия. Последнюю колонку удалить нельзя.                                  |

`placement` задаёт ID соседних колонок в форме
`{beforeColumnId, afterColumnId}`; на краю любой сосед может быть `null`. Для
удаления непустой колонки нужен либо
`{strategy: "moveCards", targetColumnId, expectedRevision}`, либо
`{strategy: "deleteCards", confirmDeleteCards: true, expectedRevision}`. Для
пустой колонки достаточно `{expectedRevision}`.

На доске может быть не более 10 колонок. Название колонки после удаления
пробелов по краям содержит 1–80 символов, а `voteLimit` — целое число от 0 до 20.

### Карточки и пагинация

| Метод и путь                                     | Доступ                                    | Запрос                                          | Результат                                                   |
| ------------------------------------------------ | ----------------------------------------- | ----------------------------------------------- | ----------------------------------------------------------- |
| `GET /api/boards/{boardId}/cards`                | Участник доски                            | Параметры `{columnId, cursor?, limit?}`         | Страница элементов одной колонки.                           |
| `POST /api/boards/{boardId}/cards`               | Участник доски                            | `{columnId, text, author?}`                     | `201` с ревизией и карточкой.                               |
| `PATCH /api/boards/{boardId}/cards/{cardId}`     | Владелец или создатель в текущем членстве | `{text?, author?}`                              | Ревизия и карточка.                                         |
| `POST /api/boards/{boardId}/cards/{cardId}/move` | Владелец или создатель в текущем членстве | `{targetColumnId, placement, expectedRevision}` | Ревизия и карточка. Сначала нужно разгруппировать карточку. |
| `DELETE /api/boards/{boardId}/cards/{cardId}`    | Владелец или создатель в текущем членстве | `{expectedRevision}`                            | Ревизия.                                                    |

В параметрах страницы обязателен `columnId`. `limit` по умолчанию равен 50 и
поддерживает значения 1–100. Ответ содержит
`{columnId, revision, items, totalCount, nextCursor}`. Передавайте непрозрачный
`nextCursor` без изменений, чтобы получить следующую страницу той же доски и
колонки. Некорректный, устаревший или не соответствующий контексту курсор
возвращает `400 INVALID_CURSOR`.

Текст карточки после удаления пробелов по краям содержит 1–1000 символов.
`author` равен `null` либо содержит 1–120 символов после такой обработки. Общий
лимит карточек задаётся `BOARD_CARD_LIMIT` и обеспечивается транзакционно.

Положение элемента задаётся через `{before, after}`, где каждая ненулевая ссылка
имеет форму `{kind: "CARD" | "GROUP", id}`. Ссылки описывают соседние
верхнеуровневые элементы в целевой колонке. Если конкурентная работа делает
положение устаревшим, сервер возвращает конфликт ревизии.

### Голоса

| Метод и путь                                       | Доступ         | Запрос                                            | Результат                                                                                                           |
| -------------------------------------------------- | -------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `PUT /api/boards/{boardId}/cards/{cardId}/vote`    | Участник доски | Без тела запроса                                  | `{revision, cardId, voteCount, viewerHasVoted, remainingVotesInColumn}`. Повторный запрос идемпотентен.             |
| `DELETE /api/boards/{boardId}/cards/{cardId}/vote` | Участник доски | Без тела запроса                                  | Та же форма состояния голоса. Повторный запрос идемпотентен.                                                        |
| `POST /api/boards/{boardId}/votes/reset`           | Владелец       | `{confirmation: "RESET_VOTES", expectedRevision}` | Ревизия и число удалённых голосов.                                                                                  |
| `POST /api/boards/{boardId}/cards/{cardId}/like`   | Участник доски | Без тела запроса                                  | Устаревший адаптер совместимости. Возвращает `Deprecation: true`; новые клиенты должны использовать `PUT .../vote`. |

Один идентификатор посетителя в рамках доски может проголосовать за карточку
один раз и не более `voteLimit` целевой колонки. Нулевой лимит отключает
голосование в колонке. Источником истины служат голоса и слоты квоты PostgreSQL.

### Группы

| Метод и путь                                          | Доступ   | Запрос                                                         | Результат                                                                        |
| ----------------------------------------------------- | -------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `POST /api/boards/{boardId}/groups`                   | Владелец | `{columnId, cardIds, primaryCardId, title?, expectedRevision}` | `201` с ревизией и группой.                                                      |
| `PATCH /api/boards/{boardId}/groups/{groupId}`        | Владелец | `{title?, primaryCardId?, expectedRevision?}`                  | Ревизия и группа. При изменении основной карточки обязателен `expectedRevision`. |
| `POST /api/boards/{boardId}/groups/{groupId}/move`    | Владелец | `{targetColumnId, placement, expectedRevision}`                | Ревизия и группа.                                                                |
| `POST /api/boards/{boardId}/groups/{groupId}/ungroup` | Владелец | `{expectedRevision}`                                           | Ревизия и восстановленные верхнеуровневые карточки.                              |

Новая группа содержит 2–100 уникальных карточек одной колонки.
`primaryCardId` должен входить в `cardIds`. Название группы равно `null` либо
содержит 1–120 символов после удаления пробелов по краям.

### Задачи

| Метод и путь                                                  | Доступ   | Запрос                                                                                | Результат                   |
| ------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------- | --------------------------- |
| `POST /api/boards/{boardId}/action-items`                     | Владелец | `{source: "manual", text, assignee?}` или `{source: "card", sourceCardId, assignee?}` | `201` с ревизией и задачей. |
| `PATCH /api/boards/{boardId}/action-items/{actionItemId}`     | Владелец | Одно или несколько из `{text?, assignee?, completed?}`                                | Ревизия и задача.           |
| `POST /api/boards/{boardId}/action-items/{actionItemId}/move` | Владелец | `{placement, expectedRevision}`                                                       | Ревизия и задача.           |
| `DELETE /api/boards/{boardId}/action-items/{actionItemId}`    | Владелец | `{expectedRevision}`                                                                  | Ревизия.                    |

Введённый вручную текст после удаления пробелов по краям содержит 1–1000
символов. При создании задачи из карточки копируется текущий текст карточки и
сохраняется ссылка на источник. `assignee` равен `null` либо содержит 1–120
символов после такой обработки. Доска поддерживает не более 200 задач.

Положение задачи задаётся через
`{beforeActionItemId, afterActionItemId}`, где на любом краю сосед может быть
`null`.

### Приглашения и членства

| Метод и путь                                              | Доступ                                   | Запрос                                                       | Результат                                                                                  |
| --------------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| `POST /api/invitations/redeem`                            | Cookie посетителя и исходное приглашение | `{token, displayName?}`                                      | Данные членства: ID доски и членства, роль и отображаемое имя.                             |
| `GET /api/boards/{boardId}/invitations`                   | Владелец                                 | Без тела запроса                                             | `{invitations}` с метаданными, использованием и активным состоянием; без исходных токенов. |
| `POST /api/boards/{boardId}/invitations`                  | Владелец                                 | Необязательный `{maxUses}`; без тела — значения по умолчанию | `201` с ID, сроком, `maxUses` и единожды возвращаемым исходным `joinPath`.                 |
| `DELETE /api/boards/{boardId}/invitations/{invitationId}` | Владелец                                 | Без тела запроса                                             | `204`; отзывает активное приглашение участника.                                            |
| `GET /api/boards/{boardId}/members`                       | Владелец                                 | Без тела запроса                                             | ID текущего членства владельца и список активных участников.                               |
| `DELETE /api/boards/{boardId}/members/{membershipId}`     | Владелец                                 | Без тела запроса                                             | `204`; отзывает активное членство участника.                                               |
| `PATCH /api/boards/{boardId}/membership`                  | Участник доски                           | `{displayName}`                                              | Обновлённое отображаемое имя и ревизия доски.                                              |
| `DELETE /api/boards/{boardId}/membership`                 | Участник                                 | Без тела запроса                                             | `204`; выход из доски. Владелец вместо этого должен удалить доску.                         |

Приглашение участника по умолчанию допускает одно использование и принимает
`maxUses` от 1 до 100. Обычно оно истекает через семь дней либо вместе с доской,
если это произойдёт раньше. URL имеет форму `/join#token`; обращайтесь с ним как
с предъявляемым реквизитом доступа.

Одна сессия может владеть не более чем 20 активными досками. На одной доске
допускается не более 20 активных приглашений участников, 100 активных
участников, 500 строк приглашений участников за всё время и 500 строк членств
участников за всё время; исчерпание лимита возвращает `422`.

### Экспорт

| Метод и путь                            | Доступ         | Результат                                                     |
| --------------------------------------- | -------------- | ------------------------------------------------------------- |
| `GET /api/boards/{boardId}/export.json` | Участник доски | Загружаемый снимок JSON.                                      |
| `GET /api/boards/{boardId}/export.csv`  | Участник доски | Загружаемый CSV в UTF-8 с BOM и нейтрализацией формул таблиц. |
| `GET /api/boards/{boardId}/export.md`   | Участник доски | Загружаемая экранированная сводка Markdown.                   |

Экспорт содержит полное состояние доски, а не данные с пагинацией, и поэтому
имеет отдельные защитные ограничения. Для слишком большой доски возвращается
`422 BOARD_EXPORT_LIMIT_EXCEEDED`.

### События реального времени

`GET /api/boards/{boardId}/events` открывает поток SSE для участника доски.
Клиент может передать последнюю полностью применённую десятичную ревизию в
`Last-Event-ID`.

Сервер отправляет:

```text
event: board.ready
data: {"boardId":"...","revision":"12"}

id: 13
event: board.invalidate
data: {"boardId":"...","revision":"13","type":"card.created"}
```

`board.invalidate` означает «загрузить авторитетное состояние не ниже этой
ревизии» и не содержит изменённый ресурс. Если `Last-Event-ID` отстаёт от
текущего состояния, первое уведомление об изменении имеет тип `resync`.
Комментарий `: heartbeat` записывается каждые 12 секунд. Доступ повторно
проверяется каждые 30 секунд; соединение закрывается при потере доступа или
недоступности слушателя PostgreSQL.

Ответы используют `text/event-stream`,
`Cache-Control: no-store, no-transform` и `X-Accel-Buffering: no`. Прокси не
должны буферизовать, кешировать или сжимать поток.

### Проверка работоспособности

`GET /api/health` не требует аутентификации:

- `200 {"status":"ok"}` означает, что конфигурация среды выполнения допустима,
  процесс принимает трафик и PostgreSQL ответил на лёгкий запрос в пределах
  тайм-аута проверки.
- `503 {"status":"unavailable"}` означает, что одна из этих проверок не прошла.

Проверка не доказывает актуальность миграций, работу `LISTEN` для обновлений,
успешность очистки или возможность восстановить резервные копии.

## Ревизии и конкурентные изменения

Мутации порядка и разрушительные мутации включают `expectedRevision`. Объекты
положения описывают предполагаемых соседей элемента. Сервер блокирует доску,
проверяет ревизию и положение, применяет изменение, увеличивает ревизию и
публикует уведомление об изменении в одной транзакции.

Устаревший запрос обычно получает:

```json
{
  "error": {
    "code": "STALE_BOARD_REVISION",
    "message": "...",
    "details": {
      "currentRevision": "13"
    }
  }
}
```

Обновите доску, постройте положение по новому состоянию и при необходимости
попросите пользователя повторить действие. Не воспроизводите разрушительный
запрос для новой ревизии автоматически.

## Ошибки

JSON-ошибки имеют единую форму в пределах конкретной ревизии исходного кода:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "...",
    "details": {}
  }
}
```

`details` необязателен и содержит только безопасные структурированные сведения.
Текущие сообщения ошибок являются текстом интерфейса и могут локализоваться;
клиентам следует ветвиться по статусу HTTP и `error.code`, одновременно считая коды
привязанными к версии, поскольку API не обещает публичную совместимость.

Частые статусы:

| Статус | Значение                                                                                                                                             |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `400`  | Некорректный UUID, параметр запроса, курсор, JSON, длина содержимого, ревизия или неожиданное тело запроса.                                          |
| `401`  | Анонимная сессия неактивна в потоке, где ошибка не маскируется как отсутствие доски.                                                                 |
| `403`  | Неверный источник, требуется роль владельца или создателя карточки либо операция запрещена.                                                          |
| `404`  | Нет доступа к доске или запрошенный ресурс в рамках доски невидим.                                                                                   |
| `409`  | Устаревшая ревизия, функция только для чтения или отключена, повторная устаревшая отметка «нравится», состояние владения или иной доменный конфликт. |
| `413`  | Тело запроса превышает настроенный лимит.                                                                                                            |
| `415`  | Конечная точка JSON не получила `application/json`.                                                                                                  |
| `422`  | Исчерпан лимит доски, колонки, приглашений, участников, голосов, экспорта или истории.                                                               |
| `429`  | Превышен лимит запросов или потоков. По возможности ответ содержит `Retry-After`.                                                                    |
| `500`  | Неожиданная внутренняя ошибка с обобщённым ответом.                                                                                                  |
| `503`  | PostgreSQL или настройка обновлений в реальном времени временно недоступна.                                                                          |

## Текущие ограничения частоты

Эти значения — детали реализации, а не гарантия уровня обслуживания. Обычные
ограничения посетителя используют идентичность, производную от реквизита.
Ограничения по доверенному IP — дополнительные пределы защиты от
злоупотреблений; они действуют только при ненулевом и корректно настроенном
`TRUSTED_PROXY_HOPS`.

| Область операции                         | Лимит посетителя | Лимит доверенного IP |     Окно |
| ---------------------------------------- | ---------------: | -------------------: | -------: |
| Создание доски                           |               10 |                  100 | 10 минут |
| Стандартная мутация содержимого          |               30 |                  300 | 1 минута |
| Создание или удаление голоса             |               20 |                  200 | 1 минута |
| Снимок доски и чтение страницы элементов |              120 |                1 200 | 1 минута |
| Установление SSE-соединения              |               30 |                  300 | 1 минута |
| Экспорт                                  |               10 |                  100 | 1 минута |
| Погашение приглашения                    |               20 |                  200 | 10 минут |

Маршруты управления приглашениями и участниками имеют отдельные ограничения для
посетителя от 5 до 60 запросов в минуту. Устаревший адаптер отметок «нравится»
допускает 20 запросов посетителя и 200 запросов с доверенного IP в минуту.
Широкий предел до аутентификации по доверенному IP в 3 000 запросов в минуту
охватывает подходящие маршруты досок и приглашений.

Счётчики ограничения частоты хранятся в PostgreSQL и общие между репликами. SSE
дополнительно разрешает не более трёх одновременных потоков для одного
идентификатора посетителя в рамках доски в каждом процессе приложения; этот
предел одновременности не является глобальным между репликами.

## Рекомендации по совместимости

- Не используйте отрисованный HTML как API.
- Не создавайте и не сохраняйте cookie посетителя другого пользователя.
- Не декодируйте курсоры и не рассчитывайте на неизменность полей сортировки
  базы.
- Не выводите наличие доступа из UUID доски или предыдущего успешного ответа.
- Считайте SSE только уведомлением об изменении и всегда обновляйте авторитетное
  состояние.
- Ожидайте, что в будущих коммитах интерфейс и API будут меняться атомарно.
