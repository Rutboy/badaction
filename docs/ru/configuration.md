# Конфигурация

Badaction читает настройки среды выполнения из переменных окружения. При
разработке из исходного кода обычно загружается игнорируемый `.env`,
скопированный из `.env.example`. Docker Compose читает переменные на хосте и
передаёт свои значения `DOCKER_*` в переменные среды выполнения внутри
контейнеров приложения и мигратора.

Никогда не добавляйте реальные файлы окружения в коммиты. Используйте хранилище
секретов или принадлежащий оператору файл с ограниченными правами и не печатайте
развёрнутые значения окружения в CI или журналах поддержки.

`NODE_ENV`, `PORT` и `HOSTNAME` — настройки процесса/платформы, а не
продуктовая конфигурация Badaction. Образ приложения фиксирует их как
`production`, `3000` и `0.0.0.0`. Меняйте привязку порта хоста Compose через
`APP_PORT`; не меняйте порт контейнера без соответствующей настройки образа и
проверок работоспособности. `NEXT_RUNTIME` и `NEXT_PHASE` задаются Next.js,
оператору не следует их устанавливать.

### Канонический источник

`APP_ORIGIN` является авторитетным для проверки источника мутаций и ссылок
восстановления владельца. Точное совпадение означает, что схема, хост и явно
указанный нестандартный порт совпадают с заголовком `Origin` браузера. Это
разные источники:

```text
https://retro.example.com
https://retro.example.com:8443
http://localhost:3000
http://127.0.0.1:3000
```

Разрешена только HTTP-форма с `localhost` и только локально. Обратный прокси не
компенсирует неверный `APP_ORIGIN`; укажите публичный HTTPS-источник напрямую.

### URL базы и схема

Миграции, запросы Prisma, прямые запросы очистки, рекомендательная блокировка и
путь `LISTEN/NOTIFY` протестированы с PostgreSQL 16 и схемой `public`. Типичный
URL приложения в production:

```text
postgresql://badaction_app:URL_ENCODED_PASSWORD@postgres:5432/retro?schema=public
```

Имя хоста `postgres` допустимо внутри сети Compose. Запущенный на хосте процесс
из исходного кода обычно использует `localhost` и `POSTGRES_PORT`. Если внешний
поставщик требует TLS, добавьте поддерживаемые им параметры SSL и проверьте
Prisma и слушатель обновлений. Не используйте пулер только для транзакций:
`LISTEN` и рекомендательные блокировки требуют постоянных сессий.

Базовая production-конфигурация Compose использует отдельный URL мигратора. Его
роль может создавать и изменять объекты в `public`; роль долгоживущего
приложения получает только права на данные, необходимые текущей схеме. Роли,
пароли и оба URL должны быть разными.

Альтернативные схемы PostgreSQL не поддерживаются текущими эксплуатационными
запросами. Изменить только параметр `schema` в URL Prisma недостаточно.

### Секреты приложения и ротация

Генерируйте каждый секрет независимо, например командой
`openssl rand -hex 32`. В production среда выполнения проверяет длину, признаки
распространённых шаблонных заглушек и попарное различие трёх значений.

Встроенной ротации с двумя одновременно действующими ключами нет. Считайте
прямую замену инцидентом или согласованной миграцией данных:

- ротация `VISITOR_TOKEN_SECRET` делает существующие cookie посетителей
  недействительными и меняет идентификаторы голосующих в рамках доски;
  существующие строки голосов остаются, но браузеры больше не предъявляют
  прежнюю идентичность;
- ротация `BOARD_ACCESS_SECRET` меняет хеши сессий и приглашений, поэтому
  существующие членства и исходные токены приглашений нельзя разрешить по
  текущим реквизитам браузера;
- ротация `RATE_LIMIT_KEY_SECRET` меняет пространство имён ключей ограничения
  частоты и фактически прерывает связь с существующими корзинами.

До изменения любого из этих значений создайте резервную копию, определите
восстановление пользователей и откат и проверьте ротацию на восстановленной
копии. Потеря текущих значений имеет те же последствия, что и ротация.

## Настройки Docker Compose

Основной Compose-файл предназначен для локальной разработки через интерфейс
обратной петли. Для общего или публичного использования переопределение для
production и `deploy/production.env.example` требуют значения оператора.

| Переменная                     | Базовое значение                 | Поведение в production               | Назначение                                                                                                                                           |
| ------------------------------ | -------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `COMPOSE_PROJECT_NAME`         | Определяется каталогом           | В шаблоне `badaction-production`     | Даёт production-стеку и его именованному тому стабильное пространство имён, отдельное от локального быстрого запуска.                                |
| `POSTGRES_DB`                  | `retro`                          | Необязательна; шаблон задаёт `retro` | База, создаваемая образом PostgreSQL при пустом томе.                                                                                                |
| `POSTGRES_USER`                | `postgres`                       | Обязательна в production override    | Административная роль, создаваемая образом PostgreSQL в пустом томе. Приложение её не использует.                                                    |
| `POSTGRES_PASSWORD`            | `postgres`                       | Обязательна в production override    | Начальный пароль административной роли `POSTGRES_USER`. В production используйте независимое значение длиной не менее 32 символов.                   |
| `POSTGRES_MIGRATOR_USER`       | Нет                              | Обязательна в production override    | Роль без прав суперпользователя, которая получает `CREATE` на базу для создания `public`, затем создаёт объекты миграций в этой схеме и владеет ими. |
| `POSTGRES_MIGRATOR_PASSWORD`   | Нет                              | Обязательна в production override    | Пароль роли мигратора. Он должен содержать не менее 32 символов и отличаться от паролей администратора и приложения.                                 |
| `POSTGRES_RUNTIME_USER`        | Нет                              | Обязательна в production override    | Роль без прав суперпользователя с доступом к данным, но без права создавать объекты схемы.                                                           |
| `POSTGRES_RUNTIME_PASSWORD`    | Нет                              | Обязательна в production override    | Пароль роли долгоживущего приложения. Он должен содержать не менее 32 символов и отличаться от паролей администратора и мигратора.                   |
| `POSTGRES_PORT`                | `5432`                           | Необязательна                        | Публикует PostgreSQL как `127.0.0.1:<value>`. Не меняет внутренний порт `5432`.                                                                      |
| `APP_PORT`                     | `3000`                           | Необязательна                        | Публикует приложение как `127.0.0.1:<value>`. Не меняет внутренний порт `3000`.                                                                      |
| `DOCKER_DATABASE_URL`          | Предсказуемый локальный URL      | Не используется production override  | Передаётся обоим контейнерам только базовым Compose-файлом для локальной разработки.                                                                 |
| `DOCKER_MIGRATOR_DATABASE_URL` | Нет                              | Обязательна в production override    | Передаётся одноразовому мигратору как `DATABASE_URL`; для встроенного сервиса используйте роль мигратора и `postgres:5432`.                          |
| `DATABASE_RUNTIME_ROLE`        | Нет                              | Выводится из `POSTGRES_RUNTIME_USER` | Внутренняя настройка мигратора: его обёртка проверяет имя роли и после применения миграций отзывает у неё доступ к таблице `_prisma_migrations`.     |
| `DOCKER_RUNTIME_DATABASE_URL`  | Нет                              | Обязательна в production override    | Передаётся долгоживущему приложению как `DATABASE_URL`; используйте ограниченную роль приложения и конечную точку с поддержкой постоянных сессий.    |
| `DOCKER_APP_ORIGIN`            | `http://localhost:3000`          | Обязательна в production override    | Передаётся как `APP_ORIGIN`; используйте внешний HTTPS-источник, а не адрес обратной петли для обратного прокси.                                     |
| `DOCKER_VISITOR_TOKEN_SECRET`  | Предсказуемое локальное значение | Обязательна в production override    | Передаётся как `VISITOR_TOKEN_SECRET`.                                                                                                               |
| `DOCKER_BOARD_ACCESS_SECRET`   | Предсказуемое локальное значение | Обязательна в production override    | Передаётся как `BOARD_ACCESS_SECRET`.                                                                                                                |
| `DOCKER_RATE_LIMIT_KEY_SECRET` | Предсказуемое локальное значение | Обязательна в production override    | Передаётся как `RATE_LIMIT_KEY_SECRET`.                                                                                                              |
| `BADACTION_DOMAIN`             | Нет                              | Обязательна для слоя Caddy мастера   | Публичное DNS-имя сайта Caddy. Указывайте только имя без схемы, порта, пути и завершающей точки.                                                     |
| `CADDY_ACME_EMAIL`             | Нет                              | Обязательна для слоя Caddy мастера   | Контактный email для автоматического управления TLS-сертификатами Caddy. Это не учётная запись приложения.                                           |
| `DOCKER_RUNNER_IMAGE`          | `badaction-runner:local`         | Необязательна                        | Выбирает готовый образ приложения. Используйте его с соответствующим образом мигратора.                                                              |
| `DOCKER_MIGRATOR_IMAGE`        | `badaction-migrator:local`       | Необязательна                        | Выбирает готовый образ мигратора. Используйте его с соответствующим образом приложения.                                                              |

Runtime-переменные `TRUSTED_PROXY_HOPS`, `BOARD_RETENTION_DAYS`,
`BOARD_CARD_LIMIT`, `RETENTION_CLEANUP_ENABLED`,
`RETENTION_CLEANUP_INTERVAL_MINUTES` и `RETENTION_CLEANUP_BATCH_SIZE`
передаются Compose под теми же именами и используют значения по умолчанию из
таблицы среды выполнения.

Необязательный `docker-compose.quick-start.yml` используется только мастером
установки. Он требует `BADACTION_DOMAIN` и `CADDY_ACME_EMAIL`, публикует Caddy на
TCP-портах 80 и 443 и сохраняет данные сертификатов Caddy в именованных томах.
Установщик также пишет `BADACTION_INSTALLER_MANAGED=1` как маркер владения для
своей команды управления; приложение и сервисы Compose его не используют. Для
прямого пути Caddy к приложению сохраняйте `DOCKER_APP_ORIGIN` равным
`https://<BADACTION_DOMAIN>`, а `TRUSTED_PROXY_HOPS` — равным `1`.

Настройки `POSTGRES_*` и `deploy/init-production-db.sh` инициализируют только
пустой каталог данных PostgreSQL. Их изменение после создания именованного тома
не переименовывает базу, не создаёт роли, не выдаёт права и не меняет пароли.
Изменяйте существующий том средствами администрирования PostgreSQL, затем
обновите соответствующий URL и перезапустите затронутый сервис. Никогда не
удаляйте именованный том для применения настройки, если все его доски нельзя
удалить или они не восстановлены в другом месте. Изменение
`COMPOSE_PROJECT_NAME` выбирает другой стек и том, но не переносит данные.

Для локальной разработки согласуйте `APP_PORT` с `DOCKER_APP_ORIGIN`. За
обратным HTTPS-прокси `DOCKER_APP_ORIGIN` является внешним источником, а
`APP_PORT` — только порт вышестоящего сервера на интерфейсе обратной петли.

| `DOCKER_SMOKE_SKIP_BUILD`                  | `0` или `1`                                                  | При `1` команда `test:docker` пропускает сборку и требует `DOCKER_RUNNER_IMAGE` и `DOCKER_MIGRATOR_IMAGE`.                                                                                                                   |
| `DOCKER_SMOKE_PRODUCTION`                  | `0` или `1`                                                  | При `1` команда `test:docker` подключает production override и проверяет отдельные роли мигратора и приложения без прав суперпользователя.                                                                                   |
| `CI`                                       | Задаётся поставщиком CI                                      | Включает более строгую проверку случайно сфокусированных и нестабильных тестов Playwright, а также отчёты CI.                                                                                                                |

`UPDATE_PRODUCT_SCREENSHOT` устанавливается внутри обёртки `docs:screenshot`;
используйте npm-скрипт вместо ручного задания переменной.

Каждое средство запуска тестов, которое создаёт, удаляет, завершает срок или
перезаписывает данные, должно работать с изолированной базой PostgreSQL.
Временная схема Prisma не делает ценную базу безопасной. Поддерживаемые команды
приведены в [Разработке](development.md).

## Предварительная проверка конфигурации

Для базовой конфигурации Compose проверьте обязательную интерполяцию, не выводя
расширенную модель с секретами:

```bash
docker compose \
  --env-file .env.production \
  -f docker-compose.yml \
  -f docker-compose.production.yml \
  --profile app \
  config --quiet
```

После запуска запросите `/api/health` и выполните функциональные проверки из
[Развёртывания](deployment.md). Проверка работоспособности проверяет форму
настроек среды выполнения и короткий запрос к базе, но не состояние миграций,
сеансовое поведение обновлений, выполнение очистки, резервные копии или
конфигурацию прокси.
