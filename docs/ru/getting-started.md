# Начало работы

Badaction можно полностью запустить в контейнерах либо разместить Node.js на
хосте, а PostgreSQL — в контейнере. Оба варианта используют одну и ту же цепочку
прямых миграций Prisma.

Интерфейс приложения сейчас доступен на русском языке. Английская, русская и
испанская версии документации описывают одно и то же поведение приложения.

## Требования

Для контейнерного варианта установите Docker с BuildKit и командой Compose v2
(`docker compose`). Проект не устанавливает минимальную версию Docker или
Compose.

Для разработки из исходного кода используйте:

- Node.js 22.23.2;
- npm 10.9.8;
- PostgreSQL 16;
- Playwright 1.62.1 с соответствующей сборкой Chromium — только для браузерных
  тестов.

Точные версии Node и npm записаны в `.nvmrc` и `package.json`. Другие основные
версии PostgreSQL не поддерживаются, поскольку цепочка миграций зависит от
поведения PostgreSQL 16.

## Быстрый запуск в контейнерах

Клонируйте репозиторий и запустите профиль приложения:

```bash
git clone https://github.com/Rutboy/badaction.git
cd badaction
docker compose --profile app up --build
```

Compose запустит PostgreSQL, один раз применит миграции, а затем запустит
контейнер приложения без прав `root`. Откройте <http://localhost:3000>.
Проверьте готовность:

```bash
curl --fail http://localhost:3000/api/health
```

Стандартные реквизиты намеренно являются предсказуемыми значениями для
разработки. Порты базы данных и приложения привязаны к интерфейсу обратной петли,
поэтому эту конфигурацию Compose нельзя напрямую открывать для сети.

Остановите запущенный на переднем плане стек сочетанием `Ctrl+C`, затем удалите
его контейнеры и сеть:

```bash
docker compose --profile app down
```

Именованный том `postgres-data` останется и сохранит доски между перезапусками.
Чтобы окончательно удалить эту локальную базу данных, и только когда её данные
можно безвозвратно удалить, выполните:

```bash
docker compose --profile app down --volumes
```

Если порт 3000 занят, согласованно измените публичный порт и канонический
источник:

```bash
APP_PORT=3100 DOCKER_APP_ORIGIN=http://localhost:3100 \
  docker compose --profile app up --build
```

Настройка production намеренно отличается. До открытия экземпляра следуйте
[руководству по развёртыванию](deployment.md).

## Настройка разработки из исходного кода

Установите закреплённые зависимости из `package-lock.json`, создайте локальный
файл окружения и запустите PostgreSQL:

```bash
npm ci
cp .env.example .env
docker compose up -d postgres
npm run prisma:generate
npm run prisma:deploy
npm run dev
```

Откройте <http://localhost:3000>. Секреты для разработки из `.env.example`
предназначены только для окружения на интерфейсе обратной петли. Не используйте
их в общем или публичном экземпляре и не добавляйте `.env` в коммит.

Остановите Next.js сочетанием `Ctrl+C`. Остановите базу данных, не удаляя её
том:

```bash
npm run db:stop
```

## Браузерные тесты

Один раз установите поддерживаемый браузер Playwright:

```bash
npx playwright install chromium
```

Браузерные тесты и тесты базы данных намеренно требуют явного подтверждения,
что данные можно удалять. До их запуска прочитайте [Разработка](development.md)
и никогда не направляйте эти команды на базу с нужными данными.
