# Badaction documentation

The English documentation is the source of truth. Russian and Spanish pages
are translations intended to make self-hosting and contribution easier. If a
translation differs from the English page or the application, follow the
application behavior and open a documentation issue.

## Use and self-host Badaction

- [Getting started](getting-started.md) — run the local container stack or a
  source-development environment.
- [Deployment](deployment.md) — configure the production Compose baseline,
  HTTPS proxy, migrations, and PostgreSQL connections.
- [Configuration](configuration.md) — runtime, Compose, and test environment
  variables.
- [Operations](operations.md) — health checks, backups, restore, upgrades,
  retention cleanup, and owner recovery.
- [Troubleshooting](troubleshooting.md) — diagnose common setup, database,
  cookie, and realtime problems.

## Understand and contribute

- [Architecture](architecture.md) — application layers, data model, access
  model, realtime updates, and background work.
- [Security and privacy](security-and-privacy.md) — trust boundaries, stored
  data, credentials, retention, and operator responsibilities.
- [Development](development.md) — repository structure, local checks, database
  tests, migrations, and screenshots.
- [Browser API](api.md) — the internal, unstable HTTP interface used by the web
  application.

Project-wide policies are in [Contributing](../CONTRIBUTING.md),
[Security](../SECURITY.md), [Support](../SUPPORT.md), and the
[Code of Conduct](../CODE_OF_CONDUCT.md).
